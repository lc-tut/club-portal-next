# P0:土台とCI

このフォルダはClubPortalの作業フォルダ。まず`CLAUDE.md`、`docs/requirements.md`、`docs/design.md`を全部読むこと。web-app-developmentスキルがあれば、着手前に読み込むこと。

今回の範囲は要件定義の第11節のP0だけ。P0の完了条件を満たしたら止まって報告し、P1には進まないこと。

着手前に「作るファイル」「テスト方針」「確認したいこと」を短く出し、私の返事を待つこと。

## 1. リポジトリの準備(各操作の前に必ず確認を取る)

このフォルダはまだgitリポジトリではない。手元にあるのは`CLAUDE.md`(下書き)、`.claude/`(権限設定、hook、スキル、サブエージェント)、`.gitignore`、`docs/`だけ。

1. `.claude/`がなく`_claude/`だけがある場合は、作業を始めずに、私に`_claude/`を`.claude/`へリネームしてClaude Codeを起動し直すよう伝えて止まる。
2. `git init`し、今あるファイルを最初のコミットにする(hookの`check-commit`が動くことも確かめる)。
3. GitHubの既存の`lc-tut/club-portal-next`を`archive-club-portal-next`にリネームし、アーカイブする。
4. 空いた名前で`lc-tut/club-portal-next`を新規作成する。公開範囲(public/private)は作成前に私に聞くこと。
5. remoteを設定し、pushする。

## 2. P0で作るもの

- `mise.toml`:python、uv、node、pnpm、dbmate、sops、ageのバージョン固定と、タスク(`dev`、`test`、`lint`、`migrate`、`gen-api`)
- `compose.dev.yaml`(PostgreSQLのみ)と、本番用`compose.yaml`の骨組み(caddy、frontend、backend、db。非root、読み取り専用ルート、DBのポートは公開しない)
- backend:uv+FastAPI。要件定義の第6節の層構成(`domain`、`usecase`、`adapter/http`、`infrastructure`)のディレクトリ、`/api/health`のみ、ruff、mypy(`--strict`)、import-linter(依存の向きの検査)、pytest
- `db/migrations`:dbmateの初期設定。素のSQLで書く
- `api/openapi.yaml`:FastAPIからの出力をコミットし、CIで差分を検査する
- frontend:Next.js(App Router)+pnpm、vitest、Storybook、ESLint(`dangerouslySetInnerHTML`の禁止を含む)、`openapi.yaml`からの型生成
- `.github`:CI(第10節)、セキュリティスキャン(第9節)、`pull_request_template.md`(第10節の内容をそのまま使う)、CODEOWNERS、Renovateの設定
- `secrets/.sops.yaml`:受信者の公開鍵は私に聞くこと。推測で埋めない
- `.claude/`:P0で決まったコマンドに合わせて、`settings.json`の`allow`や`hooks/format.sh`に直すところがあれば提案する
- `CLAUDE.md`:「コマンド」の節を実際のコマンドで埋め、下書きの注記を外す。変更内容は私に確認してからコミットする

## 3. 守ること

- TDD:ヘルスチェックも、テストを先に書いて失敗を確認してから実装する(要件定義の第10節の手順)。
- フレームワーク、ツール、GitHub Actionsのバージョンと書き方は、記憶で書かず公式ドキュメントで確認する。
- push、リポジトリの作成・リネーム・アーカイブ、リポジトリ設定の変更(ブランチ保護など)、シークレットの登録は、実行前に確認を取る。
- 要件定義に書かれていない判断が必要になったら、選択肢と推奨を出して止まる。決まったことは`docs/requirements.md`に書き戻す。

## 4. 完了条件

`mise run dev`で起動し、ヘルスチェックのテストとCIがすべて通ること。完了したら、`docs/requirements.md`の第11節のP0の状態を「完了」にする。

報告には、作ったもの、確認した結果、私に決めてほしいことを短くまとめる。
