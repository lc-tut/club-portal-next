# フェーズの実装

対象のフェーズ:$ARGUMENTS

## 1. 読む

1. `CLAUDE.md`、`docs/requirements.md`、`docs/design.md`を読む。
2. `docs/requirements.md`の第11節で、対象フェーズの「内容」「完了条件」「状態」を確かめる。前のフェーズが「完了」でなければ、進めずにそのことを報告して止まる。
3. `docs/prompts/`に対象フェーズのファイル(例:`p1.md`)があれば読み、その指示を優先する。

## 2. 計画を出して待つ

次の3つを短く出し、利用者の返事を待つ。返事があるまで実装しない。

- 変更・作成するファイル
- 書くテスト(受け入れ条件ごとに、どの層のテストで確かめるか)
- 確認したいこと(要件定義に書かれていない判断は、選択肢と推奨を添える)

## 3. 実装する

受け入れ条件ごとに次を繰り返す。

1. テストを書き、失敗することを確かめてコミットする(`test:`)。
2. テストが通る最小の実装を書く(`feat:`)。
3. テストを通したまま整理する(`refactor:`)。

区切りごとに`/check`を実行する。新しいAPIを足したら権限表テストに行を足し、`mise run gen-api`で`api/openapi.yaml`とフロントの型を更新する。UIを作ったら状態ごとのstoryを足し、design-reviewerサブエージェントに見せる。認証・認可・入力・画像・秘密情報に触れたら、security-reviewerサブエージェントに見せる。

## 4. 止まって報告する

完了条件をすべて満たしたら:

1. `docs/requirements.md`の第11節で、対象フェーズの「状態」を「完了」にする。決まったことがあれば該当する節にも書き戻す。
2. 作ったもの、確かめた結果、利用者に決めてほしいことを短く報告する。
3. 次のフェーズには進まない。
